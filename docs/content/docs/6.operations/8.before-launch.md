Most of what apps forget is checked by one test. Add it before you launch. It
fails when a raw function can run without a check, when a table keeps a
deleted person's data, when housekeeping is not scheduled, or when a public
write has no limit. Each problem names the fix. See
[Launch check](/docs/build/functions/testing#launch-check) for the details.

```ts [convex/launch.test.ts]
import { launchProblems } from '@lupinum/better-convex-functions/test'
import { expect, test } from 'vitest'

import crons from './crons'
import { fns } from './functions'
import schema from './schema'
import { modules } from './test.setup'

// Catches the mistakes that hurt after launch: a raw Convex function, a table that keeps a
// person's data after they delete their account, housekeeping nobody schedules, and a public
// write without a limit. Each problem names the fix.
test('the app has no launch problems', async () => {
  const trustedRoutes = { '/api/auth/': 'Better Auth endpoints; the auth library checks each one.' }
  expect(await launchProblems({ modules, schema, crons, fns, trustedRoutes })).toEqual([])
})
```

## What the library does for you

| Area                         | What it does                                                                                                                       | Details                                                             |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Rate limits                  | Limits how often a public action runs. The limit is per person by default.                                                         | [Rate limits and audit log](/docs/build/functions/limits-and-audit) |
| Audit log                    | Records who changed which rows.                                                                                                    | [Rate limits and audit log](/docs/build/functions/limits-and-audit) |
| Account deletion and erasure | Lets people delete their own account and erases the data your app holds about them.                                                | [Account deletion](/docs/build/authentication/account-deletion)     |
| Sign-in rate limits          | Better Auth limits sign-in attempts. This is already on.                                                                           | [Better Auth](https://www.better-auth.com/docs)                     |
| Agents housekeeping          | Deletes old agent data on a schedule: activity after one year, decided requests after 90 days, finished in-app runs after 30 days. | [The MCP door](/docs/build/agents/mcp-door#run-the-housekeeping)    |

## What you set up yourself

| Need                         | Use                                                                                                                 | Why it matters                                                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Background retries           | [Convex Workpool](https://www.convex.dev/components) or Action Retrier component                                    | Without retries, a failed background call stays failed, and no one runs it again.                                       |
| Multi-step work              | [Convex Workflow](https://www.convex.dev/components) component                                                      | Without it, a process that stops halfway stays half done.                                                               |
| Data migrations              | [Convex Migrations](https://www.convex.dev/components) component                                                    | Without it, old rows can keep a shape that the new code does not read.                                                  |
| Counts and totals            | [Convex Aggregate](https://www.convex.dev/components) component                                                     | Without it, counts get slow as the table grows, or they drift from the rows.                                            |
| Billing                      | [Convex Polar or Stripe](https://www.convex.dev/components) component (their Better Auth plugins are not supported) | Without it, you write the payment and subscription code yourself, and a missed event leaves a paid user without access. |
| Transactional email delivery | [Resend](https://www.convex.dev/components) component behind the `email` hook                                       | Without it, sign-in and verification emails may not arrive.                                                             |
| Invitations                  | [Better Auth](https://www.better-auth.com/docs) organization plugin                                                 | Without it, you write team invites and their access checks yourself.                                                    |
| Email verification           | [`requireEmailVerification`](https://www.better-auth.com/docs) in Better Auth                                       | Without it, anyone can sign up with an address they do not own.                                                         |
| Session and device list      | Better Auth [`listSessions` / `revokeSession`](https://www.better-auth.com/docs)                                    | Without it, a person cannot see or end a session on a lost device.                                                      |
| Bot protection               | Cloudflare Turnstile checked on the server                                                                          | Without a server check, a bot can skip the widget and send requests directly.                                           |
| Data region                  | Choose EU when you create the deployment (it cannot be changed later)                                               | Without the right region, personal data sits where your users do not expect it, and you cannot move it later.           |
| Backups                      | Convex backups, and test one restore                                                                                | Without a tested restore, a backup can exist and still fail when you need it.                                           |
| Separate dev and production  | Separate deployments and secrets                                                                                    | Without them, test data reaches real users, and a test key can change production data.                                  |
| Monitoring                   | Convex log streams                                                                                                  | Without them, you learn about production errors from your users.                                                        |

This page is a checklist, not a compliance guarantee.
