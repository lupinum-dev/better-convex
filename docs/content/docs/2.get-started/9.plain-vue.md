`@lupinum/better-convex-vue` gives a plain Vue app the same browser composables
that the Nuxt module uses: queries, pagination, mutations, actions, forms, file
uploads, and connection state. It clears user data when the user changes.

It does not depend on Nuxt or Better Auth. Use the Nuxt module when you need
server rendering, Nuxt server routes, or the built-in Better Auth setup.

## Install

```bash
pnpm add @lupinum/better-convex-vue@next convex@^1.42.2 vue@^3.5.0
```

The package needs `vue` `>=3.5.0 <4` and `convex` `>=1.42.2 <2`. The `next`
dist-tag is the 1.0 release candidate.

## Anonymous application

Install one plugin at the Vue application root:

```ts [src/main.ts]
import { createApp } from 'vue'
import { createBetterConvex } from '@lupinum/better-convex-vue'

import App from './App.vue'

const app = createApp(App)

app.use(
  createBetterConvex({
    convexUrl: import.meta.env.VITE_CONVEX_URL,
  }),
)

app.mount('#app')
```

Set `VITE_CONVEX_URL` in `.env.local` to your deployment URL. It ends in
`.convex.cloud`. The Convex dashboard shows it in the deployment settings.

Run `npx convex dev` in the project folder. It connects a deployment, writes
`VITE_CONVEX_URL` to `.env.local`, creates the `convex/` folder, and keeps
`convex/_generated/api` up to date while it runs.

Add the Convex functions that the component below uses:

```ts [convex/schema.ts]
import { defineSchema, defineTable } from 'convex/server'
import { v } from 'convex/values'

export default defineSchema({
  notes: defineTable({ title: v.string() }),
})
```

```ts [convex/notes.ts]
import { v } from 'convex/values'

import { mutation, query } from './_generated/server'

export const list = query({
  args: {},
  handler: (ctx) => ctx.db.query('notes').order('desc').take(50),
})

// This anonymous example lets anyone rename a note. A real application checks
// the user and their permission in the mutation.
export const rename = mutation({
  args: { id: v.id('notes'), title: v.string() },
  handler: async (ctx, { id, title }) => {
    await ctx.db.patch(id, { title: title.trim().slice(0, 200) })
  },
})
```

Add a note in the Convex dashboard (Data → `notes` → Add) so the list is not
empty.

When your application has sign-in, store the owner on each note and check it in
the mutation. `ctx.auth.getUserIdentity()` works with every auth provider. It does not check that the session is still valid. With the Nuxt module's auth, use `auth.requireUser(ctx)` instead (see [Protect data](/docs/get-started/protect-data)):

```ts [convex/notes.ts]
import { ConvexError, v } from 'convex/values'

import { mutation } from './_generated/server'

// Needs `ownerId: v.string()` on the `notes` table.
export const renameOwn = mutation({
  args: { id: v.id('notes'), title: v.string() },
  handler: async (ctx, { id, title }) => {
    const identity = await ctx.auth.getUserIdentity()
    const note = await ctx.db.get(id)
    if (!identity || !note || note.ownerId !== identity.subject) {
      throw new ConvexError({ code: 'NOTE_NOT_FOUND' })
    }
    await ctx.db.patch(id, { title: title.trim().slice(0, 200) })
  },
})
```

Then use the composables in components. They return refs right away. You do not
await them:

```vue [src/components/Notes.vue]
<script setup lang="ts">
import { api } from '../../convex/_generated/api'
import { useConvexMutation, useConvexQuery } from '@lupinum/better-convex-vue'

const { data: notes, status, error } = useConvexQuery(api.notes.list, {})
const { mutate: renameNote, pending: renaming } = useConvexMutation(api.notes.rename)
</script>

<template>
  <p v-if="status === 'pending'">Loading…</p>
  <p v-else-if="error">Could not load notes.</p>
  <ul v-else>
    <li v-for="note in notes" :key="note._id">
      <button :disabled="renaming" @click="renameNote({ id: note._id, title: `${note.title}!` })">
        {{ note.title }}
      </button>
    </li>
  </ul>
</template>
```

Render the component from the root:

```vue [src/App.vue]
<script setup lang="ts">
import Notes from './components/Notes.vue'
</script>

<template>
  <Notes />
</template>
```

Open the app in two tabs and rename a note in one. The other tab updates
without a reload.

A query with `args: {}` may omit the arguments. Every other query needs an
argument object or `'skip'`. Pass a computed value that returns `'skip'` to
pause a query. A skipped query stops its subscription and clears its data.

Query `data` is `undefined` until a value exists. A backend `null` result is
successful data, not a loading or skip sentinel.

## Wait for data before a page shows

A page that loads its data after it appears flashes empty and then moves its
content. To show the page only when its data exists, await its queries and
render it inside Vue's `<Suspense>`. A component that awaits does not render
at all without a `<Suspense>` above it:

```vue [src/App.vue]
<template>
  <RouterView v-slot="{ Component }">
    <Suspense>
      <component :is="Component" />
    </Suspense>
  </RouterView>
</template>
```

```vue [src/pages/NotesPage.vue]
<script setup lang="ts">
import { api } from '../../convex/_generated/api'
import { useConvexQuery } from '@lupinum/better-convex-vue'

const { data: notes, error } = await useConvexQuery(api.notes.list, {})
</script>
```

When the route shows a different page component, `<Suspense>` keeps the
previous page on the screen. It shows the new page when every awaited query in
it, also in its child components, has its first result or error. The refs stay
live after the await. A navigation to the same component with other parameters
reuses the page and does not wait again; it shows `pending` while the new
arguments load.

- Start all queries of a component before you await them, then use
  `await Promise.all([first, second])`. Each separate `await` waits for the
  query before it.
- A child component starts its queries only after its parent's await is
  finished.
- The await never rejects. Read `error` for a failure.
- The await waits while authentication loads. It does not wait for a skipped
  query, a query with `immediate: false`, or an `auth: 'required'` query
  without a signed-in user or after an authentication error.

Vue marks `<Suspense>` as experimental.

## Load data before a navigation finishes

`<Suspense>` waits after the router changed the URL, and child components load
only after their parent. To load a page's data before the navigation finishes,
preload it in a router guard. This needs Vue Router 4.2 or later:

```ts [src/router.ts]
import { preloadConvexQuery } from '@lupinum/better-convex-vue'
import { createRouter, createWebHistory } from 'vue-router'
import { api } from '../convex/_generated/api'
import type { Id } from '../convex/_generated/dataModel'
import ProjectPage from './pages/ProjectPage.vue'

export const router = createRouter({
  history: createWebHistory(),
  routes: [{ path: '/projects/:id', name: 'project', component: ProjectPage }],
})

router.beforeResolve(async (to) => {
  if (to.name === 'project') {
    const id = to.params.id as Id<'projects'>
    await Promise.all([
      preloadConvexQuery(api.projects.get, { id }),
      preloadConvexQuery(api.tasks.list, { projectId: id }),
    ])
  }
})
```

The queries load in parallel. When the page and its child components call
`useConvexQuery` with the same function, arguments, and `auth`, they start with
the result. The page shows complete on its first render, and the router can
scroll to its content.

- Start every preload before the first `await` in the guard, as in
  `Promise.all` above. After an `await`, Vue Router no longer provides the app,
  and `preloadConvexQuery` throws.
- `preloadConvexQuery` resolves when the first result or error exists, or after
  5 seconds without one, for example while the app is offline. It never
  rejects for a query failure. The page's own query reports the error one
  moment after its first render.
- The subscription stays open for 5 seconds after the preload resolves, also
  when the navigation is cancelled. A page that mounts later loads its data
  again.
- Preload only data that the page reads on its first render.

## Client options

Pass supported `ConvexClient` options with `clientOptions`:

```ts
app.use(
  createBetterConvex({
    convexUrl: import.meta.env.VITE_CONVEX_URL,
    clientOptions: { verbose: import.meta.env.DEV },
  }),
)
```

`clientOptions` accepts `verbose`, `webSocketConstructor`,
`skipConvexDeploymentUrlCheck`, and `unsavedChangesWarning`. Any other key
throws a `TypeError`, because the package manages auth and client replacement.
`unsavedChangesWarning` defaults to `false`. The type is
`BetterConvexClientOptions`. An embedded app that uses `attachment` cannot pass
`clientOptions`.

## Experimental subscription retention

Pass `experimental.keepAlive` to the plugin that owns the clients:

```ts
app.use(
  createBetterConvex({
    convexUrl: import.meta.env.VITE_CONVEX_URL,
    experimental: { keepAlive: { ms: 60_000, max: 30 } },
  }),
)
```

This option keeps stopped query subscriptions open for `ms` milliseconds, up to
`max` retained handles. Start with the values above. Both must be positive safe
integers. Returning to the same query can show its current data at once while
it is retained. A user change or application disposal releases all retained
subscriptions. The dedicated anonymous `auth: 'none'` transport is not retained.

Retention is off by default and is not covered by semantic versioning. Each
retained query is re-run by Convex when its data changes, so retention can
increase backend work. An embedded application uses the owning application's
configuration; it cannot set `experimental` with `attachment`.

## Authentication with any provider

The Vue package works with any identity provider. You write an auth adapter.
The adapter reports the provider's session state and returns a short-lived
Convex token:

```ts [src/convex-auth.ts]
import type { BetterConvexAuthAdapter } from '@lupinum/better-convex-vue'

// Replace this with your identity provider's browser SDK.
interface ProviderSession {
  status: 'pending' | 'authenticated' | 'anonymous' | 'error'
  userId: string | null
  generation: number
  error: Error | null
}
declare const provider: {
  session(): ProviderSession
  onChange(listener: () => void): () => void
  refresh(): Promise<void>
}

export const auth: BetterConvexAuthAdapter = {
  snapshot: () => {
    const session = provider.session()
    return {
      status: session.status,
      identityKey: session.userId,
      sessionGeneration: session.generation,
      error: session.error,
    }
  },
  subscribe: (listener) => provider.onChange(listener),
  fetchToken: async () => {
    // Your backend returns a Convex token for the current session.
    const response = await fetch('/api/convex-token', { credentials: 'include' })
    return response.ok ? ((await response.json()) as { token: string }).token : null
  },
  refreshSession: () => provider.refresh(),
}
```

- `identityKey` is a stable user ID that is not secret. The package uses it
  only to keep one user's data apart from another's.
- `sessionGeneration` must increase whenever the session changes, including a
  new session for the same user.
- Neither value is a role or a permission.
- `fetchToken` returns a token for the session in the current snapshot, or
  `null`. If it returns a cached token, the token must belong to that session
  and not be expired. The client keeps the first confirmed token until a
  refresh shortly before its `exp`, so the token needs `iat` and `exp` claims.
- Convex reports `null` as signed out. When your token endpoint fails for a
  temporary reason (429, 5xx, network), `fetchToken` may wait and try again
  before it answers. It must settle within 60 seconds, and Convex must confirm
  the returned token within 10 seconds; otherwise the identity fails closed.
  When Convex forces a refresh (`forceRefreshToken: true`), return a new token,
  not the cached one: Convex stops refreshing when it gets the same token back.
- `tokenRefreshLeewaySeconds` (optional) sets how many seconds before `exp`
  Convex asks for the next token. The default is Convex's 10. A longer leeway
  gives `fetchToken` time to wait out a failure while the current token still
  works. Keep it well below the token lifetime.

Install the adapter with the plugin:

```ts [src/main.ts]
app.use(
  createBetterConvex({
    convexUrl: import.meta.env.VITE_CONVEX_URL,
    auth,
  }),
)
```

Your backend issues the Convex token. Never put provider secrets, cookies,
refresh tokens, deployment keys, or signing keys in the Vite bundle. Check
permissions in every protected Convex function.

## Embedded Vue applications

A Nuxt app can share its Convex connection with a separately built Vue app that
runs on the same page. Install `@lupinum/better-convex-vue@next` in the
Nuxt app too. Then read the attachment in a Nuxt component and pass it to the embedded
app:

```vue [app/components/EmbeddedHost.vue]
<script setup lang="ts">
import { createApp, type App } from 'vue'
import { createBetterConvex } from '@lupinum/better-convex-vue'

import EmbeddedApp from './EmbeddedApp.vue'

let embeddedApp: App | undefined

if (import.meta.client) {
  // useConvexAttachment() throws on the server.
  const attachment = useConvexAttachment()
  onMounted(() => {
    embeddedApp = createApp(EmbeddedApp)
    embeddedApp.use(createBetterConvex({ attachment }))
    embeddedApp.mount('#embedded')
  })
  onBeforeUnmount(() => embeddedApp?.unmount())
}
</script>

<template>
  <div id="embedded" />
</template>
```

The attachment lets the embedded app run queries and mutations as the current
user. It contains no token, cookie, or session. Do not create a second Convex
client in the embedded app, and do not pass credentials to it.

## What plain Vue does not include

- Server rendering and hydration
- Nuxt server routes and `serverConvex()`
- Better Auth setup and the auth proxy
- Route middleware
- An MCP server
- Roles and permissions

Use `@lupinum/better-convex-nuxt` for the Nuxt features. Use
[`@lupinum/better-convex-agents`](/docs/build/agents/mcp) for an MCP server.
