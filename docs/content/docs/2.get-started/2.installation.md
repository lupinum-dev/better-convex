This page creates a Nuxt app and starts it with a Convex backend on your computer. You need no Convex account. Authentication stays off until [Add authentication](/docs/get-started/add-authentication). For Vue without Nuxt, use the [plain Vue guide](/docs/get-started/plain-vue).

The finished app of this tutorial is in [`starters/tutorial`](https://github.com/lupinum-dev/better-convex/tree/main/starters/tutorial). Compare your files with it when something does not work.

## Prerequisites

- Node.js `^22.22.3`, `^24.15.0` or `>=26.0.0`
- pnpm (npm and yarn also work; change the commands)

## Create the Nuxt app

Skip this step if you already have a Nuxt 4.6 or newer app.

```bash
pnpm create nuxt@latest my-convex-app
cd my-convex-app
pnpm approve-builds
```

Pick the `minimal` template when it asks. `pnpm approve-builds` lets pnpm run the build script of `esbuild`: select it and confirm. pnpm 10 and newer block build scripts until you allow them, and Nuxt does not start without this one.

## Add the module

```bash
pnpm nuxi module add @lupinum/better-convex-nuxt@next
```

This installs `@lupinum/better-convex-nuxt` and `convex`, and adds the module to `modules` in `nuxt.config.ts`. It prints a warning that no Convex deployment URL is configured. The next step fixes that.

The `next` dist-tag is the 1.0 release candidate. Upgrading from a beta? Follow [Upgrade to 1.0](/docs/operations/upgrade-to-1-0).

## Use one dev command

In `package.json`, change the `dev` script:

```json [package.json]
{
  "scripts": {
    "dev": "better-convex-nuxt dev"
  }
}
```

Keep the other scripts. `better-convex-nuxt dev` runs `convex dev` and `nuxt dev` together. Each output line starts with `[convex]` or `[nuxt]`. Ctrl-C stops both.

::warning
The command is `better-convex-nuxt`. Do not run `npx better-convex`: that is an unrelated npm package.
::

## Start the app

```bash
pnpm dev
```

The first start takes a minute. Convex downloads a backend for your computer and starts it. Then it:

- writes the deployment name and URLs to `.env.local`;
- creates the `convex/` folder and generates `convex/_generated/api`;
- keeps running and uploads your Convex functions on every save.

When `.env.local` has the URL, Nuxt starts. Open `http://localhost:3000`. The page is empty because the app has no pages yet.

Do not commit `.env.local`. Later steps add secrets to it.

A local backend has a dashboard on your computer, where you can see your tables and logs. Open it with:

```bash
pnpm exec better-convex-nuxt convex dashboard
```

Your project now looks like this:

```text
my-convex-app/
├── app/
│   └── app.vue
├── convex/
│   ├── _generated/
│   └── tsconfig.json
├── .env.local
├── nuxt.config.ts
└── package.json
```

The module adds the `#convex/api` alias for `convex/_generated/api` and auto-imports for `useConvexQuery`, `useConvexMutation`, and the other composables.

## Use a Convex account instead

The local backend is enough for this tutorial. To use a deployment in your Convex account, stop `pnpm dev` and run:

```bash
pnpm exec better-convex-nuxt convex configure
```

It asks you to sign in to Convex and to pick or create a project, and writes that deployment to `.env.local`. `pnpm dev` then uses it. All `better-convex-nuxt` commands read the deployment from `.env.local` only.

## Check your setup

Run these checks when something does not work:

1. `pnpm exec better-convex-nuxt --version` prints the installed version.
2. `.env.local` contains `CONVEX_DEPLOYMENT` and `CONVEX_URL`.
3. `convex/_generated/api.d.ts` exists.
4. The `pnpm dev` output shows `[convex] ✔ Convex functions ready!` and the `[nuxt]` line with `http://localhost:3000/`.

If a check fails, see [Troubleshooting](/docs/operations/troubleshooting).
