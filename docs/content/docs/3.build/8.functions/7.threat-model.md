The two packages protect against **mistakes in your application code** and
against **agents** that do more than a person allowed. They do not protect
against application code written on purpose to get around them.

## What is protected

| Risk                                                                    | What stops it                                                                                             |
| ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| A query forgets a tenant filter and returns another organization's rows | Row rules check every row a handler reads. The query fails instead of returning the row                   |
| A caller sends the ID of another tenant's row                           | The tenant comes from the row, not from the caller. A tenant without a role does not exist for the caller |
| A handler writes a row the caller may only read                         | The write fails with `FORBIDDEN`                                                                          |
| A new Convex query method hands out rows without a check                | `ctx.db` has only the methods the library checks. Others fail                                             |
| A function is built with Convex's own builders and skips every check    | The no-bypass test fails. An operation that calls such a function fails and keeps nothing                 |
| Scheduled work runs after the person lost access                        | Each internal operation checks the caller, the role and the rows again                                    |
| An agent calls a tool outside the scopes the person granted             | The host does not see the tool, and the call fails                                                        |
| An agent archives, publishes or deletes without asking                  | Actions with `agents: { action: 'approve' }` wait for a person                                            |
| A person approves something that changed since the agent asked          | Approving fails with `STALE`                                                                              |
| A host retries a write                                                  | The same `request_id` runs once                                                                           |
| An agent floods the application                                         | Writes per minute, open requests and IDs per call have limits. See [Limits](/docs/build/agents/limits)    |
| Text from a row shows up as a link or HTML in an approval or a host     | Summaries are one plain line for people, and inert markdown for agents                                    |
| A person disconnects a host, signs out, or loses a membership           | The next call of that agent fails                                                                         |

## The guarantee is a test

Convex cannot inspect a function before it runs. So the rule that every
function goes through `defineFunctions` is kept by a test, not at runtime:
`unguardedFunctions` in [Test your app](/docs/build/functions/testing#no-raw-functions).
Run it in CI. The runtime checks (the argument shape, the result envelope,
the rollback) are the second line.

## What is not protected

- **Code that is written to get around the library.** A handler can import
  Convex's raw builders, call `trusted`, or use a job's database without rules.
  The packages make this visible in review; they do not prevent it.
- **Your own rules.** `user`, `roleOf`, the row rules and the policy are the
  source of truth. A `roleOf` that returns `'owner'` for everyone gives
  everyone every action.
- **Effects outside the database.** An action has no transaction. A message
  sent or a payment made before a later step fails stays done.
- **The auth component.** Sessions, OAuth tokens and consent are checked by
  Better Auth through `createBetterConvexAuth`. See
  [Security model](/docs/operations/security-model).
- **What a model does with text.** See the next section.

## Prompt injection

A tool result can contain text that someone else wrote: a crawled page, a
customer's message, the name of a project. A model can read instructions in
that text and follow them. Escaping does not stop this. Inert markdown stops a
link from rendering; it does not stop a model from obeying the words.

Plan for an agent that follows instructions from data:

- **Grant narrow scopes.** A host that only needs to read gets only read
  scopes. It does not see the write tools.
- **Use `approve` for every destructive action:** delete, archive, publish,
  send, pay, invite, or change a role. The person reads the summary, which
  your `approval` function builds from the rows, before anything happens.
- **Keep the limits on.** They bound what one connection can do in a minute.
- **Read the activity feed.** Every agent write is in the feed of its
  tenant, with the tool, the person and who approved it.

## Review these by hand

Search the code for each one and check the reason:

- `trusted(` and `trustedRoutes`: functions and routes without the library.
- `unchecked(`: tables without a row check.
- `job(`: code that runs as the system, with every tenant's rows.
- `public` in the policy: actions for signed-out visitors.
- `crossTenant: true`: operations that move rows between tenants.
- Agent rules set to `'allow'` for actions that change data.
