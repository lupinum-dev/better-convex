---
title: Cacheable public pages
description: Render public pages without the session so a CDN or ISR cache can share the HTML.
navigation:
  icon: i-lucide-globe
---

With authentication on, the server reads the session cookie on every page, exchanges it for a Convex session token, and renders the page for that user. The response gets `Vary: Cookie`, and a response for a signed-in user gets `Cache-Control: private, no-store`. A shared cache, such as Vercel ISR or a CDN, must not store such a page.

Turn off session resolution during server rendering for pages that look the same for every visitor. The server then renders these pages as an anonymous visitor:

- It ignores the session cookie and does not call the token exchange.
- It adds no `Vary: Cookie` and no `private` cache header.
- `useConvexAuth()` reports `anonymous` during server rendering.
- Queries with `auth: 'optional'` run anonymously. Queries with `auth: 'required'` do not run on the server.

The browser reads the session after hydration, as for any other page.

## Turn it off for some routes

Set the `convex.ssrAuth` route rule:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  modules: ['@lupinum/better-convex-nuxt'],
  convex: {
    auth: { origin: process.env.SITE_URL ?? 'http://localhost:3000' },
  },
  routeRules: {
    '/**': { isr: 86400, convex: { ssrAuth: false } },
    '/admin/**': { isr: false, convex: { ssrAuth: true } },
  },
})
```

## Turn it off for all routes

Set `auth.ssr: false`. A route rule with `convex: { ssrAuth: true }` turns it on again for matching routes.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
  convex: {
    auth: { origin: process.env.SITE_URL ?? 'http://localhost:3000', ssr: false },
  },
  routeRules: {
    '/account/**': { convex: { ssrAuth: true } },
  },
})
```

## Protected pages

The server does not know the visitor on these routes, so the route middleware does not redirect during server rendering. The browser applies `convexAuth` after the session loads. Keep SSR auth on for protected pages when the server must redirect before it sends HTML.

## Show user-specific parts

Render parts that depend on the user in the browser only, for example with `<ClientOnly>`, or after `await useConvexAuth().ready()`. The server HTML must not contain them, because every visitor gets the same HTML.

Combine this with [`client.connect: 'on-demand'`](/docs/build/application-behavior/on-demand-client) to keep the Convex and Better Auth clients off these pages as well.
