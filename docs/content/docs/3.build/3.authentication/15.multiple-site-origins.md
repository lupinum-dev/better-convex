One Convex deployment can serve several Nuxt applications on different domains, for example one site per customer. Each site keeps its own sign-in, cookies, and email links. Convex functions still decide which site a user may change.

## How it works

1. Each Nuxt application sets its own `auth.origin`, such as `https://bakery.example`.
2. The auth proxy of that application signs its origin with `BCN_AUTH_PROXY_IP_SECRET` and sends it with each auth request to Convex.
3. Convex checks the signature and that the origin is `SITE_URL` or one of `siteOrigins`. It then runs Better Auth with that origin as the base URL and the only trusted origin.

Better Auth therefore sets cookies for the site that the visitor uses, and email links and redirects point back to that site. A request with a wrong signature or an origin that is not in the list fails. The browser cannot choose the origin.

## Configure Convex

List the other origins in `createBetterConvexAuth`. `SITE_URL` stays the main origin.

```ts [convex/auth.ts]
export const auth = createBetterConvexAuth<DataModel>(components.betterAuth, {
  siteOrigins: ['https://bakery.example', 'https://florist.example'],
})
```

To keep the list in the database, pass a function. Convex calls it for each auth request with the HTTP action context:

```ts [convex/auth.ts]
export const auth = createBetterConvexAuth<DataModel>(components.betterAuth, {
  siteOrigins: async (ctx) => await ctx.runQuery(internal.sites.origins, {}),
})
```

Each entry must be an exact origin: scheme, host, and port only. A `*` is rejected; there are no wildcard origins. Keep the query small, because every auth request runs it. If the function throws or returns something else than a list of origins, the auth request fails.

## Configure each Nuxt application

Give every Nuxt application:

- its own `auth.origin` (or `SITE_URL`),
- the same `NUXT_PUBLIC_CONVEX_URL` and `NUXT_PUBLIC_CONVEX_SITE_URL`,
- the same `BCN_AUTH_PROXY_IP_SECRET` as the Convex deployment.

Without `BCN_AUTH_PROXY_IP_SECRET`, the proxy sends no origin, and Convex uses `SITE_URL`. This is only for loopback development.

## Limits

- The OAuth provider and MCP (`oauth`, `oauthProvider`) always use `SITE_URL` as the issuer. `createBetterConvexAuth` rejects `siteOrigins` together with them.
- Social sign-in providers need the callback URL of every site, for example `https://bakery.example/api/auth/callback/google`.
- Users and sessions are shared by the deployment. A session cookie is set per domain, so a user signs in on each site separately. Check in every Convex function that the user is a member of the site that the function changes.
- A session is not bound to one site. A session cookie copied from one site works on another. Cookies are separated by host name, not by port, so treat every service on a site's host name as trusted.
- Do not set `BETTER_AUTH_TRUSTED_ORIGINS`. Better Auth would add those origins next to the verified one, so the auth setup rejects it.
