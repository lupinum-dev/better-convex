---
title: Guest users
description: Give visitors a Better Auth identity and preserve guest profile data when they sign in.
---

**Experimental.** [Semantic versioning does not cover this option](/docs/reference/experimental).

Use Better Auth's anonymous plugin to give a visitor a real user and session.
`auth.requireUser(ctx)` accepts that session. Check `user.isAnonymous === true`
in Convex functions when guests must have less access. Guests have no verified email.

## Enable the plugin

Do not enable `twoFactor` together with `experimental.anonymous`. The factory
rejects this combination. Better Auth's anonymous linking hook does not wait
for two-factor verification.

Create a local auth component with `pnpm exec better-convex init`.
Add `anonymous()` to `convex/betterAuth/schemaPlugins.ts`. Keep its generated
`jwt()` entry. Regenerate the local schema:

```bash
pnpm exec better-convex auth schema \
  --config convex/betterAuth/schemaOptions.ts \
  --output convex/betterAuth
```

The plugin adds `user.isAnonymous`. The packaged component does not have this
field. Commit the generated `schema.ts` and `schemaMetadata.ts` files.
See [Better Auth plugins](/docs/build/authentication/better-auth-plugins)
for the local component setup.

```ts [convex/auth.ts]
import { createBetterConvexAuth } from '@lupinum/better-convex-nuxt/better-auth/server'

import { components } from './_generated/api'
import type { DataModel } from './_generated/dataModel'

export const auth = createBetterConvexAuth<DataModel>(components.betterAuth, {
  experimental: { anonymous: true },
})
```

You can replace `true` with Better Auth's options: `onLinkAccount`,
`emailDomainName`, `generateName`, `generateRandomEmail`, and
`disableDeleteAnonymousUser`. Schema overrides are not supported.
Custom email generators must return unique, valid email addresses.

```ts [app/convex-auth.ts]
import { defineConvexAuthClient } from '@lupinum/better-convex-nuxt/better-auth/client'
import { anonymousClient } from 'better-auth/client/plugins'

export default defineConvexAuthClient({ plugins: [anonymousClient()] })
```

Call sign-in from an event handler. Do not call it on every page load:

```ts
const { client } = useConvexAuth()
const result = await client.signIn.anonymous()
if (result.error) throw new Error(result.error.message)
```

Better Auth rejects another anonymous sign-in while the visitor has a guest
session. Better Convex exchanges that session for a Convex session token.
No separate guest session store is needed.

## Preserve profile data when the guest signs in

Better Auth calls `onLinkAccount` with the authenticated guest and the new
user. This example preserves the guest's saved display name in the new profile:

```ts [convex/auth.ts]
import { createBetterConvexAuth } from '@lupinum/better-convex-nuxt/better-auth/server'

import { components } from './_generated/api'
import type { DataModel } from './_generated/dataModel'

export const auth = createBetterConvexAuth<DataModel>(components.betterAuth, {
  experimental: {
    anonymous: {
      onLinkAccount: async ({ anonymousUser, newUser, ctx }) => {
        await ctx.context.adapter.update({
          model: 'user',
          where: [{ field: 'id', value: newUser.user.id }],
          update: { name: anonymousUser.user.name },
        })
      },
    },
  },
})
```

Use the IDs from the callback. Do not accept source or destination user IDs
from the browser. The callback's `ctx` is a Better Auth endpoint context,
not a Convex context. Its adapter accesses only the auth component.

Email sign-up does not sign the user in: Better Convex keeps `autoSignIn`
set to `false`. Keep the guest cookie and call email sign-in after sign-up:

```ts
const { client } = useConvexAuth()
const credentials = {
  email: 'visitor@example.com',
  password: password.value,
}
const signup = await client.signUp.email({ ...credentials, name: name.value })
if (signup.error) throw new Error(signup.error.message)
const signin = await client.signIn.email(credentials)
if (signin.error) throw new Error(signin.error.message)
```

The sign-in calls `onLinkAccount`. Better Auth then deletes the old guest and
its auth records. Set `disableDeleteAnonymousUser: true` only when you need
to retain that identity. That option does not expire old guests.

## Remove old guests

Choose a retention period before enabling cleanup. This example deletes guests
created more than 30 days ago, including guests with active sessions. It processes
at most 100 guests per page and deletes their auth records through the component
API. It does not delete documents in application tables.

```ts [convex/guests.ts]
import { v } from 'convex/values'

import { components, internal } from './_generated/api'
import { internalMutation } from './_generated/server'

export const pruneGuests = internalMutation({
  args: {
    cutoff: v.optional(v.number()),
    cursor: v.optional(v.union(v.string(), v.null())),
  },
  handler: async (ctx, args): Promise<null> => {
    const cutoff = args.cutoff ?? Date.now() - 30 * 24 * 60 * 60 * 1000
    const where = [
      { field: 'isAnonymous', value: true },
      { field: 'createdAt', operator: 'lt' as const, value: cutoff },
    ]
    const users = await ctx.runQuery(components.betterAuth.adapter.findMany, {
      model: 'user',
      where,
      paginationOpts: { cursor: args.cursor ?? null, numItems: 100 },
    })
    for (const user of users.page) {
      if (typeof user.id !== 'string') throw new Error('Invalid auth user ID')
      await ctx.runMutation(components.betterAuth.adapter.deleteOne, {
        model: 'user',
        where: [{ field: 'id', value: user.id }, ...where],
      })
    }
    if (!users.isDone) {
      await ctx.scheduler.runAfter(0, internal.guests.pruneGuests, {
        cutoff,
        cursor: users.continueCursor,
      })
    }
    return null
  },
})
```

```ts [convex/crons.ts]
import { cronJobs } from 'convex/server'

import { internal } from './_generated/api'

const crons = cronJobs()
crons.daily('Remove old guests', { hourUTC: 3, minuteUTC: 0 }, internal.guests.pruneGuests)
export default crons
```

Deletion removes the user's sessions and related auth records. Queries that
read those component records become current. Add cleanup for application data
in the same internal Convex mutation if your application stores guest documents.
