## Imports

The module auto-imports `serverConvex`, `getConvexUser`, `requireConvexUser`, and `toConvexH3Error` in Nitro server code. Import them explicitly inside Nuxt server code:

```ts
import { getConvexUser, requireConvexUser, serverConvex, toConvexH3Error } from '#convex/server'
```

Outside Nuxt aliases:

```ts
import { serverConvex } from '@lupinum/better-convex-nuxt/server'
```

The entry also exports the `ServerConvexValidationError` class and the `ServerConvexCaller`, `ServerConvexOptions`, and `ConvexCredential` types.

## `serverConvex`

```ts
serverConvex(event: H3Event, options?: ServerConvexOptions): ServerConvexCaller
```

Options:

```ts
type ServerConvexOptions =
  | {
      auth?: 'required' | 'optional' | 'none'
      authToken?: never
      credential?: never
    }
  | {
      auth?: never
      authToken: string
      credential?: never
    }
  | {
      auth?: never
      authToken?: never
      credential: ConvexCredential
    }

type ConvexCredential = { type: 'cookie'; value: string }
```

`authToken` accepts an already-issued Convex JWT. `credential` accepts a Better
Auth cookie header. Raw Better Auth session tokens are not a public bearer
credential. Both explicit-principal forms imply required authentication, so do
not add a redundant `auth: 'required'` field.

The caller exposes:

```ts
getToken(): Promise<string | null>
query(query, ...args: OptionalRestArgs<Query>): Promise<Result>
mutation(mutation, ...args: OptionalRestArgs<Mutation>): Promise<Result>
action(action, ...args: OptionalRestArgs<Action>): Promise<Result>
```

No-argument Convex functions omit the artificial `{}` argument. Functions with
declared arguments still require their generated argument object.

Calls reject with a `ConvexCallError` that carries `functionName`. A missing
required identity and a rejected token exchange use kind `authentication` and
code `UNAUTHENTICATED`. Invalid options and credentials throw
`ServerConvexValidationError` before network access.

Query calls stop after `convex.server.queryTimeoutMs` (8 seconds by default),
mutations after 15 seconds, and actions after 60 seconds. Every response is
capped at `convex.server.maxResponseBytes` (1 MiB by default). See
[module configuration](/docs/reference/module-configuration#server-limits).

Cookie exchange remains request-bound: use
`serverConvex(event, { credential: { type: 'cookie', value: cookieHeader } })`.
The package does not expose a raw cookie-to-token helper because a request-less
exchange cannot preserve the trusted client identity used for rate-limit
isolation.

## `getConvexUser`

```ts
getConvexUser(event: H3Event): Promise<ConvexUser | null>
```

Returns the signed-in user of the request, or `null` for an anonymous request. A build without auth always returns `null`.

The request's Better Auth session cookie is exchanged for a Convex token at most once per request. SSR hydration, repeated `getConvexUser` and `requireConvexUser` calls, and `serverConvex(event)` calls that read the request cookie share that result, so the user a route displays is the identity Convex authorizes. Only the supported Better Auth cookies are forwarded.

It rejects with an H3 error instead of returning anonymous when the identity cannot be resolved: 502 when the auth backend fails, and 500 when auth is enabled without a Convex site URL. The error body contains no credential.

The user is display identity for routing and rendering. Authorize protected data inside Convex functions, for example through `serverConvex(event, { auth: 'required' })`.

## `requireConvexUser`

```ts
requireConvexUser(event: H3Event): Promise<ConvexUser>
```

Returns the signed-in user, or throws an H3 401 error. The response `data` is a serialized `ConvexCallError` with kind `authentication` and code `UNAUTHENTICATED`. Missing, invalid, and revoked sessions all produce 401. A build without auth always throws it. Identity resolution failures reject as `getConvexUser` does.

```ts [server/api/account.get.ts]
export default defineEventHandler(async (event) => {
  setHeader(event, 'cache-control', 'private, no-store')
  const user = await requireConvexUser(event)
  return { name: user.name ?? user.email }
})
```

## `toConvexH3Error`

```ts
toConvexH3Error(error: unknown): H3Error<SerializedConvexCallError>
```

Normalizes any thrown value with `normalizeConvexError` and returns an H3 error for a Nitro response. The HTTP status follows the error kind:

| Kind             | HTTP status                                   |
| ---------------- | --------------------------------------------- |
| `authentication` | 401, or 403 when the error carries status 403 |
| `transport`      | 502                                           |
| `server`         | The application's 4xx `status`, otherwise 400 |
| `unknown`        | 500                                           |

The H3 error `data` is `error.toJSON()` without `functionName`; it keeps the application's `ConvexError` data. It never contains a raw cause, stack, credential, or the Convex function path. Log `functionName` from the original error on the server, and map the error yourself when a route must not reveal the application data. In the browser, `normalizeConvexError` revives the same `ConvexCallError` from the `FetchError` of `$fetch` or `useFetch`.

```ts [server/api/notes.post.ts]
import { api } from '#convex/api'
import { z } from 'zod'

const bodySchema = z.object({ title: z.string().min(1) })

export default defineEventHandler(async (event) => {
  const { title } = await readValidatedBody(event, bodySchema.parse)
  try {
    return await serverConvex(event, { auth: 'required' }).mutation(api.notes.create, { title })
  } catch (error) {
    throw toConvexH3Error(error)
  }
})
```

The Convex argument validator and the Convex function still enforce the contract.

## `createUserProjectionTriggers`

Import inside Convex code:

```ts
import { createUserProjectionTriggers } from '@lupinum/better-convex-nuxt/better-auth/server'
```

Options: `table`, `index`, optional `authIdField`, `createDoc`, optional `patchDoc`, optional `rebuildDoc`.

Returns user `onCreate`, `onUpdate`, `onDelete`, and `rebuild` handlers for a derived projection. Better Auth remains canonical.
