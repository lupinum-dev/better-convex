---
title: Preserve beta.3 authentication data
description: Backfill session-generation fields without replacing Better Auth identities or sessions.
---

Use this procedure only to move a populated application-owned Better Auth
component from `1.0.0-beta.3` to a release that contains
`migrateBeta3SessionGeneration`. The migration preserves Convex document IDs,
Better Auth logical IDs, accounts, sessions, session tokens, and application
references.

Do not use this procedure for the packaged ordinary-auth component. Do not use
it for another source version. Keep public traffic closed for the complete
procedure.

## Rehearse the complete change

Rehearse the forward change and rollback against a copy of the production
snapshot. Include application tables that store Better Auth logical user IDs.
The rehearsal must prove:

- every original component document ID is unchanged;
- every Better Auth logical ID is unchanged;
- each active session token is unchanged and passes `sessionAdmission`;
- each application identity reference still authorizes the same owned resource;
- strict target schema validation succeeds after the forward change;
- strict beta.3 schema validation succeeds after rollback.

## Prepare the transition

Create a complete Convex backup before the maintenance window. A Convex snapshot
preserves document IDs and references. Record user and session counts without
recording row values.

Generate the target schema and metadata pair. In the temporary
`convex/betterAuth/schema.ts`, keep the generated tables unchanged and disable
schema validation:

```ts [convex/betterAuth/schema.ts]
const schema = defineSchema(tables, { schemaValidation: false })
```

Export `migrateBeta3SessionGeneration` from the local component adapter.
Commit the transition and strict target states separately. Keep ingress closed.
Deploy with the repository-owned authority:

```bash
pnpm exec better-convex convex deploy
```

## Backfill the component

Run both preflight checks before the first write:

```bash
pnpm exec better-convex convex run --component betterAuth adapter:migrateBeta3SessionGeneration \
'{"model":"user","mode":"preflight","after":null}'
pnpm exec better-convex convex run --component betterAuth adapter:migrateBeta3SessionGeneration \
'{"model":"session","mode":"preflight","after":null}'
```

The result contains only `scanned`, `pending`, `patched`, `done`, and `nextAfter`.
It contains no identity or session values. If `done` is false, repeat the same
command with the returned `nextAfter` value. Stop on every error.

Run the forward user migration to completion. Then run the forward session
migration to completion:

```bash
pnpm exec better-convex convex run --component betterAuth adapter:migrateBeta3SessionGeneration \
'{"model":"user","mode":"forward","after":null}'
pnpm exec better-convex convex run --component betterAuth adapter:migrateBeta3SessionGeneration \
'{"model":"session","mode":"forward","after":null}'
```

Repeat both preflight checks. Each page must report `pending: 0` and
`patched: 0`. Restore
`const schema = defineSchema(tables)`. Remove the temporary adapter export.
Deploy the strict target state. Verify counts, active sessions, and application
authorization before you open traffic.

## Roll back before traffic opens

Rollback is safe only while every migrated generation is zero. Do not roll back
after a password reset, session invalidation, or another generation advance.

Redeploy the reviewed transition state. Roll back sessions to completion before
users:

```bash
pnpm exec better-convex convex run --component betterAuth adapter:migrateBeta3SessionGeneration \
'{"model":"session","mode":"rollback","after":null}'
pnpm exec better-convex convex run --component betterAuth adapter:migrateBeta3SessionGeneration \
'{"model":"user","mode":"rollback","after":null}'
```

User rollback rejects a user with more than 128 sessions or a session that still
contains a generation field. Rollback rejects every nonzero generation. A retry
may safely start again with `after: null`; rows already restored to beta.3 are
checked again and left unchanged.

Deploy the strict beta.3 source. Verify the original document IDs, logical IDs,
active sessions, and application references. If traffic opened or a generation
advanced, keep the target schema and forward-fix. Do not restore an old snapshot
over newer application writes.
