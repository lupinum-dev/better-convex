---
title: Migrate beta.3 users
description: Preserve Better Auth identities while invalidating legacy sessions.
---

Use this one-time procedure only for a reviewed, pre-customer application-owned
Better Auth component on `1.0.0-beta.3`. It preserves user document IDs, Better
Auth logical user IDs, accounts, passwords, and application references. It
deliberately deletes every existing session, so each operator must sign in
again.

Do not use this procedure for the packaged ordinary-auth component, another
source version, more than 128 users, or more than 128 sessions. Keep public
traffic closed for the complete procedure.

## Rehearse and prepare

Rehearse the forward change and rollback against a copy of the production
snapshot. Before the maintenance window:

1. Create a complete Convex backup.
2. Record user and session counts without recording row values.
3. Record the user IDs, account-to-user links, and application-owned reference
   digests that must remain unchanged.
4. Confirm both counts are at most 128.

Close auth and application ingress. While the component still runs beta.3,
delete all sessions through the existing adapter relationship engine:

```bash
pnpm exec better-convex convex run --component betterAuth adapter:deleteMany \
'{"model":"session","where":[]}'
```

Run `adapter:count` for the session model and stop unless it returns zero.
Confirm every old session token is denied.

Generate the target schema and metadata pair. In the temporary
`convex/betterAuth/schema.ts`, keep the generated tables unchanged and disable
schema validation:

```ts [convex/betterAuth/schema.ts]
const schema = defineSchema(tables, { schemaValidation: false })
```

Export `migrateBeta3UserGeneration` from the local component adapter. Commit the
transition and strict target states separately. Deploy the transition with the
repository-owned authority:

```bash
pnpm exec better-convex convex deploy
```

## Backfill users

Run the internal operator once:

```bash
pnpm exec better-convex convex run --component betterAuth adapter:migrateBeta3UserGeneration \
'{"mode":"forward"}'
```

The result contains only `scanned` and `patched`. It contains no identity or
session values. The operator fails if any session remains, if there are more
than 128 users, or if a generation is malformed or nonzero. Run it again and
require `patched: 0`.

Restore `const schema = defineSchema(tables)`, remove the temporary adapter
export, and deploy the strict target. Verify that user document IDs, logical
user IDs, account links, and application-owned reference digests are unchanged.
Sign in again, then prove the new session is admitted as the same user with the
same application permissions.

## Roll back before sign-in

Rollback is allowed only while ingress remains closed, no session exists, and
every migrated user generation is still zero.

Redeploy the reviewed transition state and run:

```bash
pnpm exec better-convex convex run --component betterAuth adapter:migrateBeta3UserGeneration \
'{"mode":"rollback"}'
```

Run it again and require `patched: 0`. Restore the strict beta.3 source and
deploy it. User and application identities remain unchanged, but the deleted
sessions do not return; sign in again after the rollback.

After sign-in, traffic, or any generation advance, keep the target schema and
forward-fix. Do not restore an old snapshot over newer application writes.
