Use `@lupinum/better-convex-nuxt/test` for deterministic component tests. It
drives the real Vue query, mutation, action, pagination, connection, and
identity lifecycles through an in-memory transport. It does not run Convex
backend functions or replace authorization tests with `convex-test`.

## Bind the Nuxt auto-imports

`mockNuxtImport` is a compile-time macro, so declare the bindings in the test
file or a shared component-test module. Keep the runtime in a hoisted holder and
create a fresh instance before each test:

```ts [tests/component/client-screen.test.ts]
import { flushPromises } from '@vue/test-utils'
import { mockNuxtImport, mountSuspended } from '@nuxt/test-utils/runtime'
import {
  setupBetterConvexTest,
  type BetterConvexTestRuntime,
} from '@lupinum/better-convex-nuxt/test'
import { beforeEach, expect, it, vi } from 'vitest'

import { api } from '#convex/api'
import ClientScreen from '~/features/clients/ClientScreen.vue'

const testState = vi.hoisted(() => ({
  convex: null as BetterConvexTestRuntime | null,
  call(name: keyof BetterConvexTestRuntime['composables'], args: unknown[]) {
    return Reflect.apply(this.convex!.composables[name], undefined, args)
  },
}))

mockNuxtImport(
  'useConvexQuery',
  () =>
    (...args: unknown[]) =>
      testState.call('useConvexQuery', args),
)
mockNuxtImport(
  'useConvexMutation',
  () =>
    (...args: unknown[]) =>
      testState.call('useConvexMutation', args),
)
mockNuxtImport(
  'useConvexAction',
  () =>
    (...args: unknown[]) =>
      testState.call('useConvexAction', args),
)
mockNuxtImport(
  'useConvexFileUpload',
  () =>
    (...args: unknown[]) =>
      testState.call('useConvexFileUpload', args),
)
mockNuxtImport(
  'useConvexAuth',
  () =>
    (...args: unknown[]) =>
      testState.call('useConvexAuth', args),
)

beforeEach(() => {
  testState.convex = setupBetterConvexTest({ auth: 'authenticated' })
})

it('renders a realtime update and creates a client', async () => {
  const convex = testState.convex!
  convex.query(api.clients.list).resolve([{ id: 'one', name: 'First' }])
  convex.mutation(api.clients.create).resolve('client-two')

  const wrapper = await mountSuspended(ClientScreen, {
    global: { plugins: [convex.plugin] },
  })
  await flushPromises()
  expect(wrapper.text()).toContain('First')

  convex.query(api.clients.list).push([
    { id: 'one', name: 'First' },
    { id: 'two', name: 'Second' },
  ])
  await flushPromises()
  expect(wrapper.text()).toContain('Second')

  await wrapper.get('form').trigger('submit')
  await flushPromises()
  expect(convex.mutation(api.clients.create).calls).toEqual([{ args: { name: 'Second' } }])
})
```

The `plugin` is required because writes and queries run through the real Vue
composables. The Nuxt auto-import binding only replaces Nuxt's SSR adapter in
this component-test boundary.

## Control lifecycle states

An operation without a configured result stays pending. Settle it when the test
has asserted the loading UI:

```ts
const create = convex.mutation(api.clients.create)
await wrapper.get('form').trigger('submit')
expect(wrapper.get('button').attributes('disabled')).toBeDefined()

create.reject(new ConvexError({ code: 'CLIENT_EXISTS' }))
await flushPromises()
expect(wrapper.get('[role="alert"]').text()).toContain('already exists')
```

Query controls support `resolve`, `push`, `reject`, typed call records, and
active-subscription counts. Pass arguments to target one query identity:

```ts
convex.query(api.clients.detail, { id: clientId }).resolve(client)
```

Without arguments, one query control supplies all argument variants for that
function reference.

Uploads use the same pattern:

```ts
const upload = convex.upload(api.files.generateUploadUrl)
const promise = wrapper.vm.startUpload(file)
upload.progress({ loaded: 50, total: 100, percent: 50 })
upload.resolve(storageId)
await promise
```

Use `convex.auth.signOut()`, `signIn(user)`, `setLoading()`, and `fail(error)` to
prove identity changes, signed-out UI, initial loading, and auth failures.
`convex.auth.client.signOut()` is also available for components that call the
integrated auth client.

## What this proves

Use the test runtime for product presentation and orchestration:

- loading, success, error, and realtime screen states;
- typed mutation/action arguments and returned values;
- upload progress, cancellation, and failures;
- authenticated, anonymous, loading, and changing identities;
- subscription cleanup when components or identities change.

Keep separate proofs for boundaries this runtime deliberately does not emulate:

- `convex-test` for validators, authorization, indexes, and transactions;
- a Nuxt SSR fixture for server fetch, payload serialization, and hydration;
- a real browser flow for routing, focus, forms, and the deployed auth origin.

This split avoids a fake database or fake SSR engine becoming a second source
of truth in application tests.
