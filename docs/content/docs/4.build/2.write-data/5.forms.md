`useConvexForm` is a submission controller, not a form framework. Your component or form library owns values, touched and dirty state, field arrays, focus, navigation, and messages. Better Convex owns the boundary between a Standard Schema and one Convex mutation.

```ts
import { type } from 'arktype'

const checkpointSchema = type({
  balance: 'number > 0',
  note: 'string',
})

const checkpoint = useConvexForm(api.accounts.createCheckpoint, {
  schema: checkpointSchema,
  toArgs: (values) => ({
    balanceCents: Math.round(values.balance * 100),
    note: values.note || undefined,
  }),
  mapError: (error) => ({
    form: convexErrorMessage(error, 'The checkpoint could not be saved.'),
  }),
})

async function save() {
  const result = await checkpoint.submit(
    { balance: balance.value, note: note.value },
    { accountId: accountId.value },
  )
  if (!result.ok) return

  toast.success('Checkpoint saved.')
  navigateTo(`/accounts/${accountId.value}`)
}
```

The schema is required. It may validate asynchronously or transform values. `toArgs` receives the parsed output; any mutation arguments it does not produce become the typed second argument to `submit()`.

## Render errors

```vue
<form @submit.prevent="save">
  <input v-model.number="balance" :aria-invalid="Boolean(checkpoint.fieldErrors.balance)" />
  <p v-for="message in checkpoint.fieldErrors.balance" :key="message">
    {{ message }}
  </p>
  <p v-if="checkpoint.formError" role="alert">{{ checkpoint.formError }}</p>
  <button :disabled="checkpoint.pending">Save</button>
</form>
```

Known top-level issue paths become field errors. Nested paths retain their complete path and route to the matching top-level field. Pathless and unknown paths remain visible as form errors.

`mapError` receives the safe `ConvexCallError`. It may map a domain error to known submitted fields or a form message. Backend validation and authorization remain canonical; browser validation is only faster feedback.

## Submission rules

- Expected validation and mutation failures resolve as `{ ok: false, error }`.
- Success resolves as `{ ok: true, data }`.
- A duplicate call while pending returns the same Promise and does not issue another mutation.
- `reset()` clears retained presentation state. It cannot cancel or roll back a mutation already accepted by Convex.
- A reset, identity change, or component disposal prevents an older completion from repopulating state.

Use `useConvexMutation` directly for concurrent calls, optimistic writes, uploads, autosave, multiple mutations, or commands that are not forms. Use a dedicated Vue form library when you need field registration, touched/dirty state, field arrays, or wizard behavior; pass its values to `submit()`.
