The reviewed 1.0 plugin profile has two sides:

- server configuration passed to `createBetterConvexAuth`;
- client plugin methods exposed through `useConvexAuth().client`.

Some plugins also change the Better Auth component schema.

## Define client plugins

Create one `convex-auth.ts` at the Nuxt `srcDir`:

```ts [convex-auth.ts]
import { organizationClient } from 'better-auth/client/plugins'
import { defineConvexAuthClient } from '@lupinum/better-convex-nuxt/better-auth/client'

export default defineConvexAuthClient({
  plugins: [organizationClient()],
})
```

The module discovers this file, prepends the required Convex client plugin, instantiates one client, and generates type registration.

The definition itself is frozen metadata. It never creates a client.

## Configure the server plugin

```ts [convex/auth.ts]
import { createBetterConvexAuth } from '@lupinum/better-convex-nuxt/better-auth/server'

import { createOrganizationOptions } from './betterAuth/schema-plugins'

export const auth = createBetterConvexAuth<DataModel>(components.betterAuth, {
  organization: createOrganizationOptions(),
  twoFactor: { issuer: 'Example' },
})
```

Server and client plugin configuration must agree. The admitted client plugins
are organization, two-factor, email OTP, and OAuth popup, and only when the
matching server capability is enabled. Unsupported plugin IDs fail during
setup instead of silently producing a client method with no maintained server
contract.

## Call a typed plugin method

```ts
const { client } = useConvexAuth()

const organizations = await client?.organization.list()
```

Call session-changing operations through this integrated `client`; every Promise-returning client operation crosses Convex identity coordination before it settles.

## Schema-changing plugins

Organization, two-factor, email OTP, and the delegated OAuth provider can add
tables or fields. The maintained path is:

1. Define environment-independent option builders in `convex/betterAuth/schema-plugins.ts`; use them from the factory and the schema-generation wrapper.
2. Default-export environment-independent build options from
   `convex/betterAuth/schema-options.ts`.
3. Generate both artifacts together:

   ```bash
   pnpm exec better-convex auth schema \
     --config convex/betterAuth/schema-options.ts \
     --output convex/betterAuth
   ```

4. Define the local component functions with `defineAuthAdapterFunctions({ schema, metadata })`.
5. Register that one local component as `betterAuth` in `convex/convex.config.ts`.
6. Create the component client with the generated local API and typecheck server/client plugin calls.

Run the command with `--check` in CI. The pair carries one deterministic fingerprint, and the adapter refuses a mismatch. Schema generation clears production auth secrets and uses only the explicit build-only options.

Use the repository's `starters/team/convex/betterAuth` and auth-security fixtures as the current reference shape.

The 1.0 profile rejects admin, API-key, passkey, arbitrary custom-schema, and
unknown plugins. Do not mount the packaged component beside the local one,
copy the adapter, or add a generic plugin escape hatch. A new plugin requires a
reviewed library release with matching factory, schema, client, route, and
security coverage.
