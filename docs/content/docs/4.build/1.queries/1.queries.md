`useConvexQuery` connects a Convex query to Nuxt SSR and Vue reactivity. It returns its refs immediately, so setup code can use them without waiting:

```ts
import { api } from '#convex/api'

const projects = useConvexQuery(api.projects.list, { archived: false })

const visibleProjects = computed(() =>
  (projects.data.value ?? []).filter((project) => !project.archived),
)
```

## Returned state

| Field       | Meaning                                                    |
| ----------- | ---------------------------------------------------------- |
| `data`      | Query result, or `undefined` before a value exists         |
| `status`    | `idle`, `pending`, `success`, or `error`                   |
| `pending`   | `true` exactly when `status` is `pending`                  |
| `error`     | Normalized `ConvexCallError`, or `undefined`               |
| `isStale`   | Same-identity previous data is visible while new args load |
| `execute()` | Start a query created with `immediate: false`              |
| `refresh()` | Re-execute the current query                               |

`undefined` means no value exists yet. `null` is ordinary successful Convex data and is never used as a loading sentinel.

## Options

```ts
const projects = useConvexQuery(api.projects.list, args, {
  auth: 'optional',
  immediate: true,
  lazy: false,
  keepPreviousData: false,
  server: true,
})
```

The complete Nuxt option set is:

- `auth`: `required`, `optional`, or `none`; defaults to `optional`.
- `keepPreviousData`: retain the previous result while different arguments load for the same identity; defaults to `false`.
- `immediate`: start during setup; defaults to `true`. When false, no SSR fetch
  or browser subscription starts until `execute()` or `refresh()`.
- `lazy`: do not block Nuxt client navigation; defaults to `false`. SSR still
  supplies hydration data. It cannot be combined with `immediate: false`.
- `server`: run the initial query during SSR; defaults to `true`. This option exists only in Nuxt.

Vue consumers use the same API without `server` or `lazy`.

## Dynamic keyed queries

`useConvexQueries(source, options)` manages a reactive keyed collection. Adding
or removing a key creates or disposes exactly one controller. Replacing the
query under an existing key creates a new identity-isolated controller. Each
entry may override `auth` and `keepPreviousData` and may omit `args` for an
empty validator. The return is `{ states, execute, refresh }`; Nuxt can await
the initial key snapshot, while later keys settle through their own state.

## Optional await

The Nuxt return value is both the immediate state above and a native Promise. Await it only when surrounding setup must wait for initial settlement:

```ts
const projects = useConvexQuery(api.projects.list, {})
const settled = await projects

if (settled.error.value) {
  // Initial query errors remain state, not rejected setup promises.
}
```

The awaited value is a separate non-Promise view of the same refs. Success, error, skip, and `server: false` all resolve; inspect `status` and `error` for the outcome.

## Arguments and skip

An exactly empty Convex validator may omit the argument slot:

```ts
const health = useConvexQuery(api.health.current)
```

A validator with any declared key still requires the argument slot, even when every key is optional:

```ts
const projects = useConvexQuery(api.projects.search, {})
```

Pass the literal `'skip'` instead of arguments when the query should be idle:

```ts
const args = computed(() =>
  selectedProjectId.value ? { projectId: selectedProjectId.value } : 'skip',
)

const project = useConvexQuery(api.projects.get, args)
```

Skipped queries do not execute and are not pending.

## Refresh and cleanup

Live queries update after relevant Convex changes without a manual refetch. Use `refresh()` for an explicit retry or operator control, not after every mutation.

The composable stops its listener with the owning Vue scope. Identity-owned data retires synchronously when the stable user identity changes. `keepPreviousData` never carries results across an identity generation.

See the [composables reference](/docs/reference/composables) for the compact contract.
